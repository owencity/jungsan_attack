# App Review 접근 준비 (2026-10-28)

기준: [FC-027](../flow-changes/2026-10-28-ios-review-access.md). 앱 담당자 부재로 CTO가 Codex에 앱 구현까지 요청했고 Git·배포 전담을 재확인했다. [앱 PR1](https://github.com/owencity/jungsan_app/pull/1)과 백엔드 PR48은 스터디용으로 보존한다. 공개 진입 URL `https://jungsan-api.devkdk.com/api/v1/review/demo`는 2026-10-30 서버0d0df31에 적용해 운영200을 확인했다. **앱 빌드9는 CTO의 Apple 약관 동의 후 attempt2에서 서명·업로드와 키 정리를 완료했다.** Apple 처리 완료·TestFlight 설치와 실제 iPhone 검증은 아직 확인 전이다. 비밀번호를 가진 데모 계정은 만들지 않는다. [실행 기록](fc027-release-2026-10-30.md)을 따른다.

## iOS 로그인 확인

카카오·Apple 각각: 앱에서 로그인 시작 → 앱 위 시스템 인증 화면 → 동의 → 자동으로 앱 복귀 → 일회용 티켓 교환 → 내 술자리. 웹은 기존 흐름, Android는 기존 HTML 수동 복귀도 확인한다. 백엔드303 테스트만으로 iOS 성공이라고 보고하지 않는다.

## 데모 시나리오

1. 로그인 화면에서 공개된 데모 진입점을 누른다. 데모임을 명시하고 실제 계정 상태와 분리한다.
2. 총무·참여자 A·참여자 B가 있는 샘플을 연다. 미응답 또는 OPEN 시나리오와 정산 이후 시나리오를 각각 준비한다.
3. 역할을 전환해 참석·음주 응답, 총무의 차수 입력, 정산 금액·근거, 보냈어요·입금 확인을 조작한다. 실제 은행 송금이 발생하는 기능이라고 설명하지 않는다.
4. 메시지 작성·신고·차단·차단 해제를 확인한다. 신고자 개인 숨김과 다른2명 신고 전체 숨김 등 실제 계약과 차이가 없는지 확인한다.
5. 상태를 초기화해 재실행할 수 있어야 한다. 목데이터 화면 캡처만 제공하는 것은 충분하지 않다.
6. 리뷰어가 요청한 링크가 어떤 화면으로 들어가는지 실제 기기에서 시험한다. 링크가 아직 구현되지 않았다면 Notes에 존재하는 것처럼 적지 않는다.

앱 PR1은 별도 가상3명과 응답 중/입금 중/완료 상태, 역할 전환·초기화·체험 종료를 제공한다. 실제 토큰·API를 사용하지 않고 데모에서 실제 API 연결을 금지한다. 실제 기능과 다른 스푼 지급은 제한했다. 앱 공통 단위 테스트210건, Android·iOS CI, iOS 시뮬레이터의 버튼 진입·역할 전환·초기화·종료 XCTest1건이 통과했다. Android 에뮬레이터에서도 응답→자동 정산→가상10,000원 표시→보냈어요→총무 확인을 조작했다. 소셜 비밀번호·JWT·서버 키는 저장소나 공개 문서에 적지 않는다.

iOS의 `simctl openurl` 캡처는 ‘앱 열기’ 확인창에서 멈췄다. 이를 데모 진입 성공으로 처리하지 않고 XCTest가 앱의 공개 데모 버튼을 실제로 조작하도록 보완했다. 외부 링크는 실제 iPhone에서 확인창의 열기를 누른 뒤 데모가 표시되는지 후속 확인한다. 최종 자동 검증 근거는 [2026-10-29 결과](../pr-reviews/2026-10-28-ios-review/final-validation-2026-10-29.json)와 두 PR을 따른다.

백엔드 공개 페이지는 고정 링크와 설치/체험 안내만 반환한다. query·헤더 입력을 HTML에 반영하지 않고 인증 정보를 발급하지 않는다. 운영200 HTML·고정 본문·캐시/CSP·쿠키 미발급과 기존 인증401을 확인했다. 새 앱에서 외부 링크를 열고 데모에 들어가는 실기기 확인은 남아 있다. 기존 일반 공유 링크와 실제 로그인은 유지한다.

## 실제 계정·탈퇴 확인

- 실제 로그인으로 생성한 별도 계정에서 설정/계좌 화면의 회원 탈퇴 진입을 확인한다.
- 서버 `DELETE /api/v1/users/me`의204와 이후 인증401, Apple 연결 해제는 실제 제공자 시험과 구분한다.
- 진행 중 술자리의409 `ACTIVE_GATHERING_EXISTS`는 기존 CTO 결정이다. 이를 숨기거나 임의 해제하지 않는다. App Review 수용 여부는 미확인이므로 심사 설명과 정책 검토 후속으로 남긴다.

## App Store Connect 입력 항목

- 새 빌드 번호와 로그인 전환 수정 설명.
- 실제 구현된 데모 진입 위치, 데모 링크와 사용 순서.
- 총무·참여자 역할 확인 방법, 제공되는 기능·제한의 정확한 설명.
- 실제 계정이 필요하면 사용할 수 있는 로그인 정보·추가 계정 정보를 비공개 심사 정보에 입력한다. 데모 지원이 미완료인데 로그인이 불필요하다고 표시하지 않는다.
- 계정 삭제 메뉴 위치와 확인 절차.

심사팀 회신은 실제 앱 빌드·기기 결과와 링크가 준비된 뒤 작성한다. 동영상은 보조 자료이며 기능 접근을 대체하지 않는다.
