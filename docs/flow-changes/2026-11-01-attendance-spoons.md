# FC-031 참석자당 총무 스푼 자동 적립

- 상태: 반영됨 — PR #53에 서버 구현·실제 MySQL/HTTP 검증, 앱 PR #4에 조회 갱신을 반영했다. 운영 배포·TestFlight 확인은 별도 후속이다.
- 결정: 총무 본인을 제외한 참여자 1명당 총무에게 10스푼을 자동 지급한다. 지급 뒤 명단 제외·응답 변경에도 회수하지 않는다. 별도 감사 버튼·완료 보너스는 지급하지 않는다.
- 참석 기준: 해당 총무 단위에서 한 차수 이상 SOBER/DRANK로 직접 또는 총무 대리 응답한 참여자. 모두 ABSENT·빈 응답·확정 시 AUTO 기본 응답만 있는 사람은 지급 대상이 아니다. 이 해석은 PR 가정으로 명시한다.
- 중복 기준: `(gatheringId, hostUserId, participantId)`에 한 번. 같은 술자리에서 같은 총무의 단위/차수를 늘려도 같은 사람은 중복 지급하지 않는다. 다른 총무에게도 참석 응답했다면 그 총무는 별도로 받는다. 다른 술자리는 새 지급이다.
- 시점: 참석 응답 변경 저장과 같은 트랜잭션. 공개 링크 열기·예상 인원 입력·술자리 생성만으로 지급하지 않는다. 기존 응답 일괄 소급 지급은 하지 않는다.
- 보존: 완료 후 술자리 삭제로 지급 내역은 함께 삭제되지만 users.spoon_count는 유지한다. 계정 탈퇴 시 해당 계정의 지급 내역은 삭제된다. 비회원은 기존 브라우저 신원을 사용하며 이름으로 중복 여부를 판단하지 않는다.
- DB/API: 022/032 spoon_attendance_rewards 유일 키와 기존 users.spoon_count 원자 증가. 새로운 지급 API는 만들지 않고 기존 응답·내 정보·술자리 조회 API를 사용한다. API v21, REQUIREMENTS v8, ERD에 반영한다.
- 동시성: 기존 단위 → 술자리 잠금 이후 수혜 사용자 행을 잠그고 지급 이력/잔액을 함께 커밋한다. 회원 가입은 좌석 INSERT 전 가입자·수혜 계정을 ID 순서로 잠가 서로의 술자리 가입 시 FK 공유 잠금 승격 교착을 막는다. 서로 다른 술자리의 동시 지급도 이전 잔액 덮어쓰기 없이 누적한다.
- 한계: 비회원 쿠키를 지우면 다른 참여자가 될 수 있다. 실명은 본인 인증 수단이 아니며 스푼은 금전 가치 없는 표시용이다. 한 번 지급 후 유지한다는 CTO 결정을 적용한다.
- 검증: Java/Kotlin 독립 정책 기대값·비교, 실제 MySQL/HTTP 중복·동시 지급·실패 롤백·제외 후 유지·총무/불참 제외·조회·삭제 보존을 확인한다.
