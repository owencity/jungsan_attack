# 2026-10-31 비회원 참여와 캡처용 정산표

## FC-028 총무 앱 유지와 참여자 비회원 웹

- **상태:** 열림 (백엔드 참여·본인 응답 1차, 웹·정산표·캡처·운영 후속)
- **바뀐 흐름:** 총무는 기존 로그인 앱을 유지한다. 참여자는 공유 링크로 모바일웹에 들어와
  성이름과 차수별 참여·음주 여부를 한 화면에서 입력한다. 회원 가입·소셜 로그인·앱 설치를
  참여 조건으로 요구하지 않는다. 기존 디자인을 유지한다.
- **백엔드 반영·근거:** 문서 PR #49의 `09a33f0` 위에 [비회원 API](../GUEST_PARTICIPATION.md)와
  API v18·ADR-023·021/031을 추가했다. 세션204·참여200·본인조회200·수정204를 제공하며
  기존 `JoinController.join`은 여전히 `@LoginUser`가 필요하다. 웹·전체 기능·운영 적용은 후속이다.

### 비회원 응답 개발 범위

1. 링크 미리보기 → 성이름·차수 응답 → 참여 및 응답 완료를 기본 흐름으로 삼는다.
   별도의 이름 등록 화면을 선행시키지 않는다. 링크 열기만으로 참여자를 만들지 않는다.
2. `전 차수 똑같이`로 입력을 줄이고, 불참 차수에는 술·음료 입력을 숨긴다.
   기존 `ABSENT/SOBER/DRANK` 계산은 유지한다. **음료 O/X의 별도 금액 분배는 미결**이며
   값을 받기만 하고 계산에 반영한 것처럼 표시하지 않는다.
3. 이름은 표시용이다. 이름 일치만으로 기존 참여자 선택·응답 수정·송금 상태 변경을
   허용하지 않는다. 같은 이름을 가진 서로 다른 참여자도 구분할 수 있어야 한다.
4. 같은 브라우저 재방문 시 본인 응답을 읽고 수정할 권한을 유지한다. 단, 기기 이동·쿠키 삭제 시
   복구 방법은 후속 계약에서 정한다. 이름 재입력으로 다른 사람의 권한을 되찾게 하지 않는다.
5. 기존 회원 총무 인증과 비회원 참여 권한을 구분한다. `@LoginUser`를 제거하는 것만으로
   기존 API를 공개하지 않는다. 비회원은 자신의 술자리·참여자 범위만 수정할 수 있어야 한다.
6. 참여와 최초 응답은 하나의 트랜잭션으로 저장한다. 더블 탭·네트워크 재시도·동시 요청으로
   같은 참여자가 중복 생성되지 않도록 요청 식별자와 DB 제약을 먼저 설계한다.
7. 단위별 명단·OPEN 수정 제한·revision/hash·자동 정산을 유지한다. 비회원 추가·수정도
   기존 계산 입력 변경으로 처리한다. 총무의 다른 단위 권한까지 넓히지 않는다.

### 자동 정산표와 캡처 공유

- **엑셀 다운로드는 개발 범위에서 제외한다.** 화면 안에 엑셀처럼 행·열로 정렬된 정산표를
  자동 표시하고, 총무가 이를 캡처해서 공유한다. 별도 Excel 파일·Google Sheets 연동은 없다.
- 현재 색상·글꼴·버튼 디자인을 유지한다. 행은 차수·항목, 열은 참여자, 마지막은 합계다.
  차수별 결제자와 최종 송금 대상도 금액과 함께 확인할 수 있게 한다.
- 총무는 전체 표를 보고 참여자는 자기 금액·송금 대상·근거를 먼저 본다. 전체 표의 공개
  범위는 비회원 조회 API 계약에서 정하며, 기존 공개 링크 미리보기에 명단·계좌를 추가하지 않는다.
- 미응답·불참·면제·0원을 구분한다. 정산 전 예상금액과 확정금액을 구분하고 캡처에는
  술자리·정산 단위·계산 상태·기준 시각을 함께 보여준다. 캡처 뒤 응답이 바뀌어도 이미지가
  갱신되는 것은 아니므로 화면에서도 현재 상태를 확인할 수 있어야 한다.
- 서버 Core 결과와 기존 확정 송금 스냅샷이 금액의 기준이다. 프론트에서 다시 나누거나
  항목별 올림으로 사람 합계·송금액을 새로 계산하지 않는다. 항목 표시·원 단위 조정의
  구체적인 응답 모양은 표시 계약에서 정한다.
- 일반 화면은 고정 열과 가로 스크롤을 사용할 수 있다. 캡처에서는 화면 밖 사람이 누락되지
  않도록 인원에 따라 표를 나누고 각 장에 차수·이름·합계 기준을 반복하는 방식을 우선 검토한다.
  캡처 이미지의 서버 저장이나 카카오톡 자동 발송은 포함하지 않는다.

### 구현 전 계약 순서

1. **비회원 권한·DB·API:** 참여자와 회원 구분, 재시도 중복 방지, 본인 권한 발급·만료·복구,
   허용 Origin/CSRF 검사, 조회 범위, 기존 회원 흐름 호환성을 정의한다. 로그인 JWT의
   httpOnly 쿠키 정책과 충돌하는 지점은 ADR로 명시한다. 기존 유효 쿠키의 범위를 무작정 넓히지 않는다.
2. **백엔드 1차:** 참여·응답 원자 저장, 본인 재조회·수정, 총무 명단 반영과 자동 정산 회귀를 구현한다.
   새 Liquibase와 `ERD.md`, `API.md` 버전 개정을 같은 구현 PR에 포함한다.
3. **모바일웹 연결:** 이름과 차수별 응답을 한 화면에 제공하고 재방문을 검증한다.
4. **정산표·캡처:** 전체 표와 개인 요약을 기존 계산 결과로 구성한다. 최종 공유 이미지는
   표 머리글·금액 잘림과 여러 장 분할을 실제 기기에서 검증한다.

비회원의 결제자 역할·계좌 등록·보냈어요·타임라인·신고/차단·스푼은 회원 ID를 전제로 한
기존 기능과 연결되므로 권한표를 별도로 대조해야 한다. 1차 응답 구현만으로 비회원 정산
전체가 완료됐다고 표시하지 않는다. 회원 전환 때 기존 비회원 신원을 합치는 정책도 후속이다.

- **기존 문서와 충돌:** FC-009의 로그인 후 참여, FC-013의 회원 최초 실명 등록을
  비회원에게 선행시키는 흐름, REQUIREMENTS v4 §3.3·§4.2. 회원 실명 등록 API 자체는 유지한다.
- **반영할 곳:** REQUIREMENTS v5(이 PR), 후속 ADR·DOMAIN/SETTLEMENT_UNITS·API·ERD·서버·웹.
- **결정 필요:** 음료 O/X가 음료값 별도 분배인지 표시만인지. 별도 분배라면 총무 입력 금액과
  술/음료 동시 선택·분모·원 단위 표시를 CALC_RULES_V2부터 정하고 Core를 확장한다.

### 완료 기준

- 비회원이 앱 설치·로그인 없이 참여하고, 같은 브라우저에서 본인 응답만 수정한다.
- 동명이인·동시 참여·재시도·다른 술자리 권한 재사용·만료/삭제·총무 권한 침범을 검증한다.
- 기존 회원 로그인·참여·신고/차단·단위별 자동 정산 테스트를 유지한다.
- 기존 디자인의 정산표에 참여자 응답이 자동 반영되고 캡처에 표 머리글과 금액이 잘리지 않는다.
- 다운로드 파일 없이 캡처로 공유할 수 있다. 구현 PR·테스트·운영 검증이 끝날 때까지 이 FC는 열림이다.
