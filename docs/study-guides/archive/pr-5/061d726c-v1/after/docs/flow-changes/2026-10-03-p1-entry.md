## FC-009 링크로 참여 — 참여와 응답을 한 요청으로, 로그인 전 미리보기

- **상태:** 열림 (계약 모양 제안 — 이름은 백엔드가 정해도 된다)
- **바뀐 흐름:** 단톡방 링크(`/jungsan/j/{shareToken}`)를 누르면 P1이 열린다. P1에서 술자리를 보고
  **차수별 응답까지 고른 뒤** [참여하고 응답 완료]를 누르면 참여·응답이 한 번에 끝난다(P1+P2 합침).
  웹은 로그인 전에도 P1이 보이고, 버튼을 누를 때 로그인한다. 링크를 연 것만으로는 참여되지 않는다.
- **백엔드 영향:**
  1. **로그인 없이 읽는 미리보기 API** — 공유 토큰으로 술자리 요약을 준다:
     `title, date, status, participantCount, host{displayName, spoonCount}, rounds[{id, seq, total}]`.
     **참여자 이름·응답·금액·계좌는 주지 않는다**(링크가 퍼져도 남의 정보가 새지 않게).
     정산 뒤(`status != OPEN`)에도 이 요약은 주되 화면은 "이미 정산된 술자리예요"만 보인다.
  2. **참여 요청에 응답을 같이 받는다** — `POST .../join` 본문에 `responses: [{roundId, type}]`(선택).
     한 트랜잭션에서: 참여자 행 추가 → `SELF` 응답 저장 → 타임라인 `JOINED`(+ 응답 소식) → `input_revision`
     올림 → 총무 알림. 프론트는 참여와 응답을 두 번 호출해도 동작하지만, 그러면 둘째 호출이 실패할 때
     "참여는 됐는데 응답 없음"이 생긴다(정산 때 자동응답으로 처리되긴 한다).
  3. **규칙** — 이미 참여 중이면 아무것도 바꾸지 않고 성공(멱등, 술자리 id 반환). `status != OPEN`이면
     거절. 새 참여자는 `EXEMPT`를 보낼 수 없다(면제는 총무만). 명단이 바뀌면 `input_revision`이
     올라가서 총무가 그 전에 받은 미리보기로는 정산하기가 409가 된다 — **의도된 동작**이다.
  4. **알림** — 총무에게 "○○님이 참여하고 응답했어요"(응답 없이 참여하면 "참여했어요").
     REQUIREMENTS §10 "참여자가 응답을 남김 → 총무"에 해당.
- **로그인 왕복 주의(웹):** 실제 카카오 로그인은 페이지를 떠났다 돌아온다. 프론트가 고르던 응답을
  `sessionStorage`에 두었다가 돌아와서 이어 보낸다 — 서버는 할 일 없음. 다만 OAuth 콜백 뒤
  **원래 링크(`/jungsan/j/{token}`)로 돌려보내는 `redirect` 보존**이 필요하다(지금 콜백은 `/jungsan`으로 간다).
- **기존 문서와 충돌:** 없음. `DOMAIN_DB_DESIGN_V2.md`의 참여 트랜잭션에 응답 동시 저장만 더하면 된다.
