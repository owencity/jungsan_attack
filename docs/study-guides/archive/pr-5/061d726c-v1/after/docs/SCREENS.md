# 정산어택 — 화면 흐름 스펙 (제품 v3)

> **상태:** 확정 · 구현 전
> **작성일:** 2026-09-29
> **대상:** 웹(`profile`, React)과 앱(`jungsan_app`, KMP — iOS·Android). **두 플랫폼이 이 문서 하나를 따른다.**
> **제품 기준:** `REQUIREMENTS.md` v3 · **데이터 기준:** `DOMAIN_DB_DESIGN_V2.md`

웹과 앱이 요구사항을 각자 읽고 화면을 짜면 흐름이 갈라진다(실제로 앱은 총무 흐름만,
웹은 모임 흐름까지 따로 자랐다). 이 문서가 화면의 단일 기준이다. 플랫폼 차이는 §7에만 적는다.

---

## 1. 설계 원칙

1. **정산방 화면 하나가 중심이다.** 총무든 참여자든 대부분의 시간을 정산방에서 보낸다.
   화면을 단계별로 쪼개 이동시키지 않는다.
2. **맨 위에는 "지금 할 일 하나"만 보인다.** 역할(총무·결제자·참여자)과 상태로 문구가 정해진다(§4).
   `OPEN`·`SETTLING` 같은 상태 이름은 화면에 쓰지 않는다.
3. **맨 아래 버튼도 하나다.** 그 "할 일"을 바로 하는 버튼. 나머지 동작은 메뉴나 목록 안에 둔다.
4. **텍스트 입력은 금액·술 항목·계좌(1회)·이름(1회)·타임라인 메시지뿐이다.** 나머지는 버튼이다.
5. **배경은 지금 것을 그대로 쓴다** — 로그인은 석양, 그 외는 앱 강변 / 웹 기존 배경.

## 2. 화면 목록

| ID | 화면 | 누가 | 한 줄 설명 |
|---|---|---|---|
| **L1** | 로그인 | 모두 | 카카오 로그인. 석양 배경 |
| **L2** | 이름 확인 | 첫 로그인만 | 카카오 닉네임을 기본값으로 표시 이름 확인 |
| **H1** | 내 술자리 | 모두 | 탭 [내가 총무] [참여 중] [완료]. 위에 내 캐릭터·칭호. [+ 새 술자리] |
| **R1** | 정산방 | 모두 | **중심 화면.** 할 일 배너 · 참여자 상태 · 타임라인 · 하단 버튼 |
| **R2** | 차수 편집 | 총무 | 금액 · 술 항목 · 결제자. 앱은 [영수증 찍기] |
| **R3** | 정산하기 확인 | 총무 | 1인당 금액 미리보기 · 자동응답 안내 · [정산하기] |
| **R4** | 참여자 관리 시트 | 총무 | 한 사람 탭 → 차수별 면제 · 내보내기 |
| **P1** | 참여 입구 | 링크로 온 사람 | 총무·차수 미리보기 · [참여하고 체크하기] |
| **P2** | 내 응답 | 참여자 | 차수별 [불참][논알코올][알코올] · [전 차수 똑같이] |
| **P3** | 내 금액 | 참여자 | 받는 사람별 금액과 근거 · [계좌 복사] · [보냈어요] |
| **A1** | 계좌 등록 | 결제자(1회) | 은행·계좌번호. 한 번 등록하면 재사용 |
| **N1** | 알림함 | 모두 | 내부 알림 목록 |

**없어지는 화면**(웹 기준): 내 모임(`GroupHomePage`), 모임 만들기(`CreateGroupPage`), 모임 상세
(`GroupDetailPage`), 모임 검색(`SearchGroupPage`), 모임 가입(`JoinGroupPage`), 이의제기 채팅
(`DisputePage`), 금액 입력의 "전부 내가 냈어요/항목마다 달라요"(`AmountPage`), 예상 인원 경고
(`ConfirmPage`의 "등록한 인원과 다릅니다"), 명단(`RosterPage` → R1 참여자 목록으로 흡수),
수집 현황(`CollectPage` → R1로 흡수), 전체 내역(`AllPage` → R1·P3 근거로 흡수).

## 3. 흐름

### 3.1 총무

```text
L1 로그인 → (L2 이름 확인, 처음만) → H1 내 술자리
  → [+ 새 술자리] ─── 입력 없이 바로 생성("9/29 술자리") ──→ R2 차수 편집(1차)
  → 금액·술 항목 → [저장] → R1 정산방
  → 하단 [링크 공유]  (사람이 들어오기 시작)
  → 하단 [정산하기] → R3 확인 → [정산하기]
  → R1: 받을 돈 목록에서 [확인] / [아직 안 들어왔어요]
  → 모두 확인되면 자동 완료 → 7일 뒤 사라짐
```

- **술자리 이름과 날짜는 입력받지 않는다.** 생성 시 `M/d 술자리`·오늘로 채우고 R1 메뉴에서 바꾼다.
- **결제자 지정은 사람이 들어온 뒤에 한다.** 생성 직후엔 참여자가 총무뿐이라 고를 사람이 없다.
  R2의 "누가 냈나요?"는 기본값 "나"이고, 참여자가 생기면 목록에서 고를 수 있다.

### 3.2 참여자

```text
카톡 링크 → P1 참여 입구(술자리 보기 + 차수별 응답 고르기)
  → [참여하고 응답 완료] (웹: 로그인 전이면 [카카오로 로그인하고 참여하기]) → R1 정산방
  → (정산되면 알림) → P3 내 금액 → [계좌 복사] → 송금 → [보냈어요]
  → (확인되면 알림) → R1에서 [🥄 한 스푼] (선택)
```

- **링크를 여는 것만으로는 참여되지 않는다.** P1에서 버튼을 눌러야 명단에 들어간다.
  단톡방 링크를 구경만 한 사람이 명단에 들어가지 않게.
- **P1과 P2를 한 화면으로 합쳤다(2026-10-03).** 처음 들어올 때 응답까지 한 번에 끝낸다 — 참여자가
  누르는 화면이 하나 준다. P2는 이후 "응답 고치기"로만 쓴다.

### 3.3 결제자 (총무가 아닌데 한 차수를 낸 사람)

참여자 흐름과 같고, 두 가지가 더해진다.
- 계좌가 없으면 R1 배너가 가장 먼저 **"받을 계좌를 등록해주세요"** → A1.
- 정산 후 R1에 **받을 돈 목록**이 생기고 [확인]·[아직 안 들어왔어요]를 누른다.

## 4. "지금 할 일" 배너와 하단 버튼 (R1)

**위에서부터 먼저 걸리는 줄 하나만 보여준다.** 배너 문구와 하단 버튼은 항상 짝이다.

**순서 원칙 — 남을 막고 있는 일이 먼저다**(2026-09-30 CTO 결정). 누가 [보냈어요]를 눌렀다면 그
사람은 내 확인만 기다리며 멈춰 있다. 내가 보낼 돈은 나만 늦어진다. 그래서 송금 중 순서는
**받은 돈 확인 → 내 송금이 안 들어왔대요 → 보낼 돈 → 받을 돈 대기**다. 총무·결제자 모두 같다.

### 4.1 총무

| 조건 | 배너 | 하단 버튼 |
|---|---|---|
| 차수가 없음 | 1차 금액을 넣어주세요 | [1차 입력] → R2 |
| 참여자가 총무뿐 | 링크를 보내서 사람들을 불러주세요 | [링크 공유] |
| 미응답자 있음 | N명이 아직 응답 안 했어요 · 준비되면 정산하세요 | [정산하기] → R3 |
| 모두 응답 | 모두 응답했어요 | [정산하기] → R3 |
| 정산됨, [보냈어요] 받은 건 있음 | ○○님이 보냈대요. 확인해주세요 | [입금 확인하기] (목록으로 스크롤) |
| 정산됨, 내 송금에 [아직 안 들어왔어요] | ○○님이 아직 입금을 확인 못 했어요 | [다시 확인 요청] |
| 정산됨, 내가 보낼 돈 있음 | ○○님께 18,000원을 보내주세요 | [보낼 돈 보기] → P3 |
| 정산됨, 받을 돈 대기 | N명 입금 기다리는 중 | [링크 다시 공유] |
| 완료 | 정산 끝! 7일 뒤 사라져요 | 없음 |

### 4.2 참여자 · 결제자

| 조건 | 배너 | 하단 버튼 |
|---|---|---|
| 결제자인데 계좌 없음 | 받을 계좌를 등록해주세요 | [계좌 등록] → A1 |
| 아직 응답 안 함 | 1차·2차 응답을 남겨주세요 | [응답하기] → P2 |
| 응답함, 정산 전 | 응답 완료! 총무가 정산하면 알려드릴게요 | [응답 고치기] → P2 |
| (결제자) [보냈어요] 받은 건 있음 | ○○님이 보냈대요. 확인해주세요 | [입금 확인하기] |
| [아직 안 들어왔어요] 받음 | ○○님이 아직 입금을 확인 못 했어요 | [다시 확인 요청] |
| 보낼 돈 있음(대기) | ○○님께 23,000원을 보내주세요 | [보낼 돈 보기] → P3 |
| 보냈어요, 확인 대기 | 확인 기다리는 중이에요 | 없음 |
| 내 송금 모두 확인, 스푼 아직 | 끝! 총무에게 한 스푼 어때요? | [🥄 한 스푼] |
| 완료 | 정산 끝! 7일 뒤 사라져요 | [🥄 한 스푼] (아직 안 줬으면) |

- 자동응답이 적용된 사람에게는 배너 아래에 한 줄을 붙인다:
  **"응답이 없어 전 차수 참석·알코올로 계산됐어요"**.

## 5. 화면별 구성

### R1 정산방

위에서 아래로:

1. **상단 줄**: 술자리 이름 · 날짜 · (총무만) ⋯ 메뉴 — 이름/날짜 바꾸기, 정산 되돌리기, 정산 끝내기
2. **총무 카드**: 국자 총무 캐릭터(칭호 단계) · 이름 · 칩 `🥄 1,280 · 프로 총무` (전설이면 `· 3위`)
3. **할 일 배너** (§4)
4. **참여자 줄**: 가로 아바타 목록. 각자 상태 점 — 정산 전: 응답함 ● / 안 함 ○,
   정산 후: 확인 ✓ / 보냈어요 … / 대기 ○. (총무는 탭하면 R4)
5. **차수 요약**: `1차 120,000 · 2차 45,000` — 탭하면 R2(총무) 또는 근거(참여자)
6. **타임라인**: 시스템 소식(⚙)과 메시지가 시간순. 🥄 소식은 강조색
7. **하단 고정**: 메시지 입력칸 + **할 일 버튼 하나**

### R2 차수 편집 (총무)

- 차수 이름(1차, 2차…)은 자동. 순서 바꾸기·삭제는 ⋯
- **금액** — 숫자 키패드. 앱은 옆에 **[영수증 찍기]** (§7)
- **술 항목** — 프리셋 칩 `소주` `맥주` `막걸리` `하이볼` `와인` + [직접 입력].
  칩을 누르면 한 줄이 생기고 병당 가격 기본값(소주 5,000 · 맥주 5,000 · 막걸리 4,000 ·
  하이볼 7,000 · 와인 30,000)과 병 수 **[−] 1 [+]** 가 붙는다. 가격은 탭해서 고친다
- **누가 냈나요?** — 기본 "나". 참여자 칩에서 고른다
- [저장] · [+ 다음 차수]

### R3 정산하기 확인 (총무)

- 처음엔 시트로 잡았지만 미리보기 목록·대리 응답까지 들어가 길어서 **웹·앱 모두 한 화면**으로 둔다
  (2026-10-01). [정산하기] 버튼은 바닥에 붙여 목록이 길어도 늘 보인다.

- 1인당 금액 미리보기 목록(서버 미리보기 결과 그대로)
- 미응답자가 있으면 경고 박스: **"민수, 지영 — 응답이 없어 전 차수 참석·알코올로 계산돼요"**.
  이름을 탭하면 그 자리에서 차수별 응답을 바꿀 수 있다(총무 대리 설정)
- "정산하면 금액이 고정돼요. 아무도 보내기 전이면 되돌릴 수 있어요."
- [정산하기] — 서버에 미리보기의 `inputRevision`·`inputHash`를 같이 보낸다. 409면
  "그 사이 응답이 바뀌었어요" 안내 후 미리보기를 새로 받는다

### R4 참여자 관리 시트 (총무)

- 그 사람의 차수별 응답 표시
- 차수별 **[면제]** 토글 — 켜면 그 칸이 `EXEMPT(HOST)`, 참여자는 못 바꾼다
- [이 술자리에서 내보내기] — 정산 전만

### P1 참여 입구

- 위: "○○님이 정산어택에 초대했어요" · 술자리 이름 · 날짜 · 이미 참여한 사람 수
- 총무 카드(캐릭터·칭호)
- **차수마다 [불참][논알코올][알코올]**(P2와 같은 줄, [전 차수 똑같이] 포함). 모든 차수를 골라야 버튼이 켜진다
- 차수가 아직 없으면 응답 없이 [참여하기] — "총무가 금액을 넣으면 알려드릴게요"
- 버튼: [참여하고 응답 완료] → R1. **웹은 로그인 전에도 이 화면이 보이고** 버튼이
  [카카오로 로그인하고 참여하기]가 된다. 앱은 딥링크로 열리면 로그인부터 거친다(§7)
- 정산된 뒤 들어오면 "이미 정산된 술자리예요"만 보이고 참여 불가. 이미 참여한 사람은 [정산방으로]
- 웹 주소 `/jungsan/j/{shareToken}`

### P2 내 응답

- 차수마다 한 줄: **[불참] [논알코올] [알코올]** 세 버튼 중 하나. **이것만 고르면 끝이다.**
  음료수 같은 추가 체크는 두지 않는다 — 참여자는 응답하고 빠졌다가, 정산되면 금액 확인·입금만 한다
  (2026-10-01 CTO 결정)
- 위에 **[전 차수 똑같이 ▾]** — 고르면 모든 차수에 같은 값
- 총무가 면제한 칸은 버튼 대신 "총무가 면제로 지정했어요 🎁" (잠김)
- [응답 완료]. 정산 전까지 다시 들어와 고칠 수 있다

### P3 내 금액

- 받는 사람별 카드: `민지님께 23,000원`
  - 근거 펼치기: 차수별 `1차 참석·알코올 18,000 + 2차 불참 0 …`
  - 받는 사람 계좌 + **[계좌 복사]**. 계좌 미등록이면 "계좌 등록을 기다리는 중"
  - **[보냈어요]** → 상태 "확인 기다리는 중"
- 여러 명에게 보내야 하면 카드가 여러 장이다

### A1 계좌 등록

- 은행(목록에서 선택) · 계좌번호 · 예금주(표시 이름 기본값). [저장] — 다음부터 재사용

### H1 내 술자리

- 맨 위: **내 캐릭터 + 칭호 + 스푼 수** (한 번도 총무를 안 했으면 "첫 정산을 만들어보세요")
- **탭 세 개: [내가 총무] [참여 중] [완료]** (2026-10-01 CTO 결정). 탭 옆에 방 수.
  - 진행 중인 방은 내 역할로 나눈다 — 내가 연 방은 [내가 총무], 남이 연 방은 [참여 중]
  - 끝난 방은 역할과 상관없이 [완료]에만. **[완료] 뱃지**와 "N일 뒤 사라져요", 흐리게
  - 각 줄: 술자리 이름 · 그 방의 할 일 한 줄. [참여 중]엔 "민지 총무", [완료]엔 내 역할(총무/참여)
  - 내가 지금 손대야 하는 방이 있는 탭엔 점(●)을 찍는다
  - 처음 열리는 탭: 할 일이 있는 탭(총무 → 참여 순) → 방이 있는 탭 → [내가 총무]
  - **줄 뱃지 — 내가 아직 확인 안 한 일**: [입금 확인](누가 보냈대요) → [정산금액 확인](정산됐는데
    내 금액을 아직 안 열어봄) → [응답하기](응답 전). 배너와 같은 순서 원칙(남을 막고 있는 일이 먼저)
- **줄을 누르면 — 참여자는 할 일 화면이 먼저**(2026-10-01 CTO 결정): 응답 전이면 P2, 정산됐는데
  금액을 안 봤으면 P3, 그 밖엔 R1. 총무는 늘 R1
- 머리 오른쪽 🔔 — 안 읽은 알림 수. 누르면 N1
- 하단 [+ 새 술자리]

### N1 알림함

| 언제 | 누구에게 | 알림 | 누르면 |
|---|---|---|---|
| 정산됨 | 총무 뺀 참여자 | **정산이 나왔어요! 입금액을 확인해주세요** · `민지님께 41,000원 외 1건` (자동응답이면 그 사실도) | P3 |
| 정산됨 + 자동응답 있음 | 총무 | 자동응답으로 계산된 사람이 있어요 | R1 |
| [보냈어요] | 받는 사람 | ○○님이 보냈대요. 입금을 확인해주세요 | R1 |
| [아직 안 들어왔어요] | 보낸 사람 | ○○님이 아직 입금을 확인 못 했대요 | P3 |
| 모두 입금 | 참여자 모두 | 정산 완료! 🎉 · 7일 뒤 사라져요 | R1 |

- 행동한 본인에게는 보내지 않는다. 같은 알림이 푸시(FCM)로도 간다.
- "정산 **완료**"는 모두 입금됐을 때만 쓴다 — [완료] 탭·뱃지와 같은 뜻으로 맞춘다. 정산하기 직후는 "정산이 나왔어요".

## 8. 프론트 데이터 모델 (목데이터 기준)

두 플랫폼이 같은 모양을 쓴다. 필드는 `DOMAIN_DB_DESIGN_V2.md`를 따른다.

```text
User          { id, displayName, spoonCount, payout? {bank, accountNo, holder} }
Gathering     { id, title, date, hostUserId, status: OPEN|SETTLING|COMPLETED,
                shareToken, completedAt?, inputRevision }
Participant   { id, userId, displayName, spoonCount, status: ACTIVE|REMOVED }
Round         { id, seq, label, total, payerParticipantId, drinks: DrinkItem[] }
DrinkItem     { name, unitPrice, quantity }
Response      { participantId, roundId, type: ABSENT|SOBER|DRANK|EXEMPT, source: SELF|AUTO|HOST }
Transfer      { id, fromParticipantId, toParticipantId, amount,
                status: WAITING|SENT|CONFIRMED, sentAt?, confirmedAt?, notReceivedAt? }
TimelineEntry { id, type: MESSAGE|SYSTEM|SPOON, authorParticipantId?, systemCode?, body, createdAt }
Spoon         { giverParticipantId }        // 이 술자리에서 준 사람 목록
```

- 칭호와 캐릭터 단계는 `spoonCount`에서 계산한다(저장하지 않는다).
- 1인당 금액은 **프론트가 계산하지 않는다.** 목데이터 단계에선 고정값을 쓰고, 백엔드가 붙으면 서버
  미리보기·정산 결과를 그대로 보여준다(계산은 `core`만 한다 — `ARCHITECTURE.md` §2.1).
