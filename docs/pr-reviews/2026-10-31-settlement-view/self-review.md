## 변경과 위험

- 확정된 개인 송금은 저장된 스냅샷에서 본인 outgoing만 읽는다. 예상 금액에는 계좌를 제공하지 않는다.
- 표의 절단 셀과 최종 배정 사이의 차이는 Core의 조정 행으로 나타낸다. 프론트는 다시 계산하지 않는다. Kotlin·Java를 독립 구현하고 기대값과 보존 법칙을 함께 검사한다.
- 총무 표 조회는 단위 총무만 허용하며 REPEATABLE_READ로 입력·응답·상태를 일관되게 읽는다. 확정 표는 재구성 결과와 저장된 송금이 다르면 거절한다.
- 비회원 보냈어요는 단위 잠금과 기존 송금 상태 정책을 공유한다. 동일 단위의 다른 참여자도 타인의 송금을 바꿀 수 없다. Origin 검사와 인증 가드에 새 핸들러를 포함한다.
- 데이터는 배치 조회한다. 신규 스키마·라이브러리·운영 설정은 없다. HTTP/JDBC/Spring 인프라는 공유하고 표시 계산은 언어별 Core가 맡는다.
- 정산표의 이름은 총무에게만 제공한다. 계좌·쿠키·인증 정보는 표와 로그에 추가하지 않는다.

## 검증과 남은 범위

- 로컬 Core 59 / Server 223, 실패·오류·건너뜀 0. bootJar 성공. 이후 표 응답의 no-store 헤더를 추가했으므로 최종 커밋은 CI에서 재검증한다.
- 실제 MySQL 검증 스크립트에 개인 정보 범위·계좌 미등록·같은 방 타인 송금 거절·동시 보냈어요·알림 1회·확정 표 불일치·빈 차수 안내를 추가했다. 실행 결과는 PR에 남긴다.
- 웹 연결·화면 캡처·운영 배포는 별도 확인 대상이다. CI의 격리 환경 검증을 운영 완료로 취급하지 않는다.

1. 차수별 셀은 정수 원 절단, 최종 차이는 하단의 수취인별 조정 행으로 표시한다. 화면에서 조정 이유가 충분히 명확한지 확인한다.
2. 비회원의 브라우저 만료·기기 이동 복구와 계좌 등록은 이번 범위 밖이다. 이름만으로 권한을 복원하지 않는다.
