# CI가 발견한 운영 DB 최초 인증 — 구현자 후속 점검

기준 `08b13a4a9c292499a4e781380af95f6c47aa7df9` → `ba508a6903a125b07383ea21927727fb31ced64f`. [실패 기록](ci-failure-01.json) · [후속 diff/가이드](../../study-guides/apple-provider-v2/guide.md).
원본 점검 뒤 실제 prod 시험에서 발견한 결함이다. 실패를 통과로 표시하지 않고 수정과 회귀 검증을 남긴다.

- 원인: MySQL 8.4 caching_sha2_password의 최초 인증에 필요한 공개키 교환이 prod JDBC URL에서 허용되지 않았다. 앞선 local URL은 허용했으므로 같은 것으로 판단할 수 없었다.
- 수정: 외부 DB 포트를 열지 않는 기존 compose 내부 연결에 옵션만 명시했다. 환경변수 기본값·스키마·업무 정책·언어 구현은 바꾸지 않았다. 새 의존성도 없다.
- 검증: actionlint 3개 workflow와 diff 문법 검사 통과. 기존 실제 MySQL 테스트는 인증 캐시를 비운 뒤 prod를 띄워 이 실패를 재현했다. 같은 최신 CI가 통과해야 병합한다.
- 가용성/보안: 공개키 교환은 서버 신원 검증을 대신하지 않는다. 외부/공유 네트워크 DB 전환 전 TLS·인증서 검증이 필요하다. 운영 키·DB 데이터·타 서비스는 수정하지 않았다.
- 기록: 실제 CI 가짜 설정의 prod 로그만 artifact에 추가한다. OCI 운영 로그는 가져오지 않는다. v1 가이드는 바이트 그대로 유지하고 v2에 실제 후속 diff를 고정했다.
- 남은 확인: 최신 CI, 운영 배포 health, 외부 카카오 인가, Apple WEB/APP 503, 실제 사용자 로그인은 별도다.
