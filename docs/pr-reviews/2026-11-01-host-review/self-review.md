# FC-029 총무 확인 후 확정 자체 점검

구현 기준: `6c34df9c7a1f7876fbaccc98da18acf49a6a3eed` → `bbfdbcdd43f809306715160833d0fd9cc8cc0330`.
PR52는 PR51 위에 쌓았으며 병합하지 않는다. 자체 점검은 CTO·시니어 승인과 다르다.

- 자동 확정의 persistSettlement 호출을 제거했다. 해당 함수는 총무 인가·OPEN·revision/hash 검사를 통과한 settle에서만 호출된다.
- 목표 인원을 초과한 응답자는 자르지 않는다. 전체 ACTIVE 명단의 응답 완료를 Kotlin/Java가 독립 판정한다. 검증 오류는 응답 저장을 취소하지 않고 공개한다.
- 명단 삭제는 기존 총무/결제자 보호, 대상 단위 응답 삭제, revision 증가를 유지한다. 다른 단위와 공유 신원은 보존한다.
- 단위→술자리 잠금 순서와 입력 해시 검사를 유지한다. preview 이후 삭제 시 409, 동시 확정 200/409 및 스냅샷 한 건을 실제 MySQL에서 검증했다.
- 새 스키마·의존성·계산식·운영 설정 변경은 없다. 기존 확정 건을 OPEN으로 변경하지 않는다.
- 공개 이름은 본인 인증이 아니다. 브라우저 쿠키 삭제 후 재응답 방지·계정 연결은 이번 범위 밖이다. 총무가 명단을 검토한다.
- 미응답 DRANK/AUTO 기본값은 변경하지 않고 미리보기 경고를 유지한다. 비회원 개인 금액/송금 API는 호환 유지하되 새 화면에서는 사용하지 않는다.
