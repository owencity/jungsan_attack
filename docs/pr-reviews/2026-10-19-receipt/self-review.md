# Spring 영수증 연결 자체 점검

대상 [PR #38](https://github.com/owencity/jungsan_attack/pull/38), `28ab9dd47f0ad6f8564b770176c7e6963f8bf67b` → `d3a91a27f0008bd0a9726738f8c701bd3dc66015`. 구현자의 자체 점검이다. 외부 리뷰를 실행하거나 CTO 승인을 받은 기록이 아니다.

- 방향: Python 개발과 독립해 저장 없는 후보 HTTP 경계를 먼저 구현했다. Java/Kotlin 정책은 독립 구현·기대값 비교, HTTP/JDBC/JSON DTO는 공유 어댑터다. core·스키마·의존성 변경은 없다.
- 권한: @LoginUser를 첫 인자로 받고 SQL은 술자리/단위/사용자에 한정한다. ACTIVE 공유·단위 명단, 총무, OPEN을 전후 확인한다. 실제 MySQL HTTP에서 다른 사용자/다른 단위/다른 부모/상태 거절을 확인했다. 인증 가드 화이트리스트를 늘리지 않았다.
- 자원: 인증·권한·설정·MIME·알려진 크기 뒤 스트림을 열고 최대 8MiB+1만 읽는다. 잘못된 multipart도 미리 파싱하지 않게 지연 설정했다. 단건 permit과 최대 만 개 고정 창만 유지하며 close 중복 호출로 permit이 늘지 않는다.
- 동시성: 창 접근·permit 획득만 모니터 안이다. 모델 호출 중 DB 트랜잭션·모니터는 유지하지 않는다. 오류와 상태 재검사 실패에도 permit을 반환한다. 재시작/다중 인스턴스의 전역 quota 보장은 없다.
- 장애: 연결/읽기 제한, 자동 재시도/리다이렉트 없음. 실제 소켓 timeout 504, 연결 거부 503, redirect 미호출을 검증했다. Python CPU 취소·느린 업로드 전체 경과 시간 제한·실제 ARM 성능은 보장하지 않는다.
- 데이터: 응답은 256KiB, schema v2·타입/범위·확인 true를 검사하고 명시 DTO만 반환한다. 미인식 null/UNKNOWN을 보정하지 않는다. 외부 오류 원문·서비스 키를 오류/로그에 넣지 않는다. 상품명 필드의 내용 익명화 보장은 아니다.
- 불변: 단위 revision·차수·정산·타임라인의 실제 DB snapshot을 대조했다. OCR 실패/재시도에도 저장하지 않는다. DB 잠금으로 응답 직후 권한 변경까지 차단하는 API는 아니다.
- 검증: 로컬 Core54/서버194 실패·오류·건너뛰기0, compileKotlin·bootJar 성공, AST/Bash 문법 확인. 원격 CI의 단계별 결과·성공 발췌는 ci-source.json 참조. 실제 MySQL/HTTP의 모의 모델 검증과 실제 Python 모델 정확도는 구분한다.
- 호환: 두 OCR 설정 모두 없으면 prod도 기동해 OCR만 503이다. 일부/잘못된 설정은 거절한다. 실제 모델·운영 내부 연결·촬영 UI·실계정 웹/앱·운영 배포는 미완료다. 기본 compose는 활성화하지 않았다.
- FC: 원격 main 3eb525464a32a3415c4d3c0db9dd6bfd9bcc3420의 열림005/009/010/011/014/015/020/021 확인. 015 권한·020 상태 적용, 나머지 출시 후속 유지. 012 결정 보류, 023 프론트 인원 기본값 후속. Python PR34의 문서/ADR 번호는 통합 시 맞춰야 한다.
- SOLID: ReceiptService가 작은 권한/외부 호출 계약에 의존해 DB·HTTP 없는 실패 검증이 가능하다. 추출 정책, 자원 입장, JSON 경계의 변경 이유가 분리됐다. 새로운 계산/저장 구조를 만들지 않았다.
- 병합: PR37 위의 분리 브랜치이며 main 병합·배포는 수행하지 않았다. 학습 가이드 생성과 사용자 진도는 별도다.
