# ADR-003 · 참여자에게 앱 설치를 요구하지 않는다

**상태** 확정 · **관련** `SPEC.md` §2, §3, §10

## 맥락

FCM은 앱에 등록된 디바이스 토큰으로 보낸다. **참여자가 웹에 머무는 한 FCM을 받을 수 없다.**
로그인 여부와 무관하다. 알림을 참여자에게 보내기 위해 앱 설치를 강제하는 안을 검토했다.

## 결정

**참여자는 웹에서 로그인하고 웹에서 체크한다. 앱 설치를 요구하지 않는다.**
FCM은 **주최자 전용**으로 한정한다.

## 근거

### ① 논리가 순환한다

```
미응답자가 문제다 → 알림으로 해결하자 → 알림엔 앱이 필요하다 → 설치를 강제하자
                                              ↓
                                  앱을 안 깐 사람이 미응답자가 된다
                                              ↑ ─── 원점
```

**설치 강제는 미응답자 문제를 해결하는 게 아니라 미응답자를 만드는 원인이 된다.**
`SPEC.md` §5가 *"정산이 그 사람 손에 인질로 잡히면 서비스가 멈춘다"* 며 최대 리스크로 지목한 바로 그 문제다.

### ② 잃는 것은 참여자가 아니라 주최자다

5명 중 2명이 설치를 거부하면 주최자는 단톡방에서 *"야 앱 좀 깔아봐"* 를 두 번 말해야 한다.
그 순간 주최자는 다음 모임에서 이 앱을 쓰지 않는다. **친구에게 뭔가를 강요하면서까지 쓸 앱이 아니다.**
주최자를 잃으면 그 모임 전체를 잃는다.

정산은 **월 1~2회짜리 일회성 이벤트**다. 참여자에게 "1년에 몇 번 쓸 앱을, 술 깬 다음날 아침에,
남의 부탁으로" 설치할 이유가 없다.

### ③ 알림은 이미 카카오톡이 하고 있다

한국에서 정산 알림의 실질적 채널은 단톡방이다. **푸시 하나가 "단톡방에 링크 카드가 뜨고
5명이 동시에 보는 것"을 이기지 못한다.** `SPEC.md` §3이 카카오톡 공유와 OG 태그를 필수로 잡은 이유다.

### ④ 알림 없이도 흐름이 끊기지 않는다

§5가 **"대신 체크"와 "언제든 확정"** 으로 미응답자 문제를 이미 해결해뒀다. FCM은 편의 기능이다.

## 대가

- **참여자는 푸시 알림을 받지 못한다.** 주최자가 단톡방에 링크를 공유해야 한다
- 참여자 웹(SSR)과 주최자 앱 두 채널을 모두 유지해야 한다. 설치를 강제했다면 앱 API 하나로 줄었다

## 만약 뒤집는다면 — 반드시 함께 해야 하는 것

설치를 강제하는 순간 `SPEC.md` §9가 범위 밖으로 못 박은 **Deferred Deep Link 문제가 되살아난다.**
웹이 완전히 동작한다는 전제가 무너지기 때문이다.

```
단톡방 링크 → 스토어 → 설치 → 앱 실행 → 어느 모임인지 모름 → 빈 화면
```

Firebase Dynamic Links는 종료됐고 Branch·AppsFlyer는 범위 밖이다.
무료 공식 대안은 **Play Install Referrer API** 하나다.

```
https://play.google.com/store/apps/details?id=app.jeongsan&referrer=token%3Dk3f9dq2
→ 설치 후 앱이 InstallReferrerClient로 읽어 해당 모임으로 진입
```

**이것 없이 설치를 강제하면 "앱 깔았는데 빈 화면"이 된다.** iOS에는 동등한 수단이 없다.

## 재검토 조건

- 참여자의 재방문율이 유의미하게 높게 나올 때 (= 일회성 이벤트라는 전제가 틀렸을 때)
- 카카오톡 공유만으로 응답률이 실제로 부족하다는 데이터가 나올 때

그 경우에도 설치 강제보다 **웹 푸시(Web Push)** 를 먼저 검토한다.
Android Chrome은 그대로 동작하고, iOS는 홈 화면 추가가 필요하다.
