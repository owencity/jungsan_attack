# ADR-023 비회원 응답은 별도 쿠키와 술자리별 권한으로 관리한다

## 맥락

FC-028은 총무의 로그인 앱을 유지하고 참여자에게는 가입 없는 모바일웹을 제공한다.
이름은 동명이인·사칭을 구분할 수 없어 수정 권한으로 사용할 수 없다. ADR-008의 전원 로그인
전제와 달라지지만 회원 인증·계좌·송금 권한은 그대로 유지해야 한다.

## 결정

먼저 `POST /api/v1/guest/session`을 완료해 브라우저 전용 JWT 쿠키를 확보한 뒤 참여 요청을 한다.
쿠키는 `jeongsan_guest`, httpOnly·SameSite=Lax·운영 Secure·host-only·Path=/api/v1/guest,
고정 30일이다. 회원 JWT와 같은 기존 서명 설정을 쓰되 purpose와 비숫자 subject로 구분한다.
비회원 토큰은 회원 인증으로, 회원 토큰은 비회원 인증으로 쓸 수 없다. 토큰 원문은 JSON·URL·로그로 주지 않는다.

`guest_participations`의 `(gathering_id, browser_hash)` 유일 키가 같은 브라우저의 술자리별
신원을 결정한다. 이름이나 클라이언트 participantId로 권한을 선택하지 않는다. 회원 연결이 NULL인
탈퇴 좌석은 이 표식이 없으므로 비회원으로 인증되지 않는다. 기존 회원 중복 방지 제약도 유지한다.

참여·초기 응답은 단위→술자리 잠금 순서의 한 트랜잭션이다. 이미 포함된 단위의 POST 재시도는
응답을 덮지 않고 현재 본인 상태를 반환한다. 이름이 다르면 409이고 수정은 전용 PUT을 사용한다.
따라서 별도 요청 UUID 대신 서버 인증한 브라우저·술자리·단위 조합이 참여 요청의 멱등 키다.
단위가 자동 정산된 뒤에도 같은 참여의 POST 재시도는 성공한다. 제외된 단위에는 재가입하지 못한다.

모든 guest 쓰기는 기존 frontend-origin과 정확히 같은 Origin을 요구한다. SameSite만으로
동일 사이트의 다른 호스트를 신뢰하지 않는다. session API도 이 규칙을 적용한다. 클라이언트는
session 초기화를 직렬화하고 완료 전에 참여를 제출하지 않는다. 무효 쿠키는 자동으로 새 신원으로
교체하지 않고 401을 반환한다. 조회는 본인 응답·관련 차수·단위 상태만 제공한다.

## 근거와 대가

- 전원 소셜 로그인보다 입력이 적고, 이름 기반 권한보다 안전하다.
- 개별 비밀 링크는 총무의 배포 부담과 URL 유출 위험이 있어 첫 단계에는 사용하지 않는다.
- 회원 쿠키에 가상 회원 ID를 넣지 않아 기존 사용자 기능으로 권한이 확대되지 않는다.
- 쿠키 삭제·만료·브라우저 변경은 본인 신원을 복구하지 못한다. 이름으로 자동 복구하거나
  기존 회원과 합치지 않는다. 다른 브라우저의 동일 인물을 자동 식별하는 보장도 없다.
- 1차 비회원은 결제자·추가 총무가 될 수 없다. 총무는 비회원에게 대리 응답·명단 제외를 할 수 있다.
  비회원 스스로의 송금 상태 변경·계좌·메시지·신고/차단·스푼은 이 PR에 없다.

## 재검토 조건

기기 이동 복구, 회원 전환, 비회원 결제자 또는 비회원 메시지를 제공할 때 권한표와 인증 수명을
다시 설계한다. 새 토큰을 단순 발급해 기존 신원과 합치거나 이름을 인증 수단으로 승격하지 않는다.
