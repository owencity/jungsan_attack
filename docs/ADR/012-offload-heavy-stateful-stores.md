# ADR-012 · 무거운 상태 저장소는 관리형 무료 티어로 오프로드한다

**상태** 확정 · **관련** `ADR-006`(대체됨) · `ADR-010` · `ADR-013`

## 맥락

`report/flow.md`가 요구하는 스택은 8종이다 — MySQL, MongoDB, Redis, Kafka, Netty,
Elasticsearch, Logstash, Kibana. 인프라는 **OCI Always Free 인스턴스 1대
(2 OCPU / 12GB)뿐**이다(콘솔 확인 완료 — 추가 인스턴스 없음).

`ADR-013`이 서비스를 3개로, 오케스트레이션을 k3s로 정한 뒤에도 전부 자체
호스팅하면 예산이 빠듯하다.

```
자체 호스팅 전부 시도 시
  k3s + Gateway + 서비스 3개                  ~2~2.4GB
  MySQL · Redis · Kafka                      ~2.3~3.8GB
  MongoDB                                    ~0.5~1GB
  Elasticsearch                              ~1~2GB
  Prometheus + Loki + Grafana                ~2~3GB
                                              ─────────
                                              ~7.8~12.2GB   ← 12GB 를 넘나든다
```

## 결정

**상태를 갖고 무거운 것부터 관리형 무료 서비스로 오프로드한다. 자체 호스팅은
가벼운 것과 트랜잭션 데이터로 제한한다.**

| 저장소 | 방식 | 이유 |
|---|---|---|
| **MongoDB** | **Atlas M0 (관리형, 오프로드)** | 채팅 메시지 저장. 512MB 무료 티어로 시작 규모에 충분 |
| **Elasticsearch** | **자체 호스팅, 마지막 단계로 유예** | `flow.md` 자신의 Phase 8(가장 마지막)과 일치. 도입 시점에 남는 용량으로 판단 |
| Logstash | **도입하지 않는다** | 채팅 색인은 Kafka 컨슈머가 직접 한다(`flow.md` 다이어그램: MongoDB→Kafka→Search Consumer→ES). 로그 수집기가 낄 자리가 없다 |
| Kibana | **도입하지 않는다** | 관측은 이미 Prometheus+Loki+Grafana. 두 회사 채용공고 어디에도 없다 |
| MySQL | 자체 호스팅 | 트랜잭션 핵심 도메인(`ADR-011`). 작은 규모라 부담 없음 |
| Redis | 자체 호스팅 | 풋프린트가 작다(~0.3GB). presence·분산락 |
| Kafka | 자체 호스팅 | MongoDB를 빼면 자리가 남는다. 안 맞으면 Redpanda(Kafka 프로토콜 호환·경량)로 대체 |

### MongoDB를 뺀 뒤 예산

```
k3s + Gateway + 서비스 3개                  ~2~2.4GB
MySQL · Redis · Kafka                      ~2.3~3.8GB
Prometheus + Loki + Grafana                ~2~3GB
                                            ─────────
                                            ~6.3~9.2GB   → 12GB 안에 여유가 생긴다
```

**Elasticsearch를 나중에 붙일 자리(~1~2GB)가 이 여유 안에 있다.** 관측 스택
리텐션을 좁히면 더 확보할 수 있다.

## 근거

- **Mongo와 ES는 상태를 크게 갖는 것들이다.** JVM 서비스나 Redis처럼 재기동해도
  가벼운 것들과 다르게, 이 둘은 디스크 용량도 함께 요구한다. 관리형이 그 관리
  부담(백업·용량 확장)까지 대신 진다
- **Elasticsearch는 채팅 검색에만 쓴다.** 채팅 기능(`ADR-010`) 자체가 마지막에
  구현되므로, 검색을 그보다 더 뒤로 미뤄도 사용자 경험에 공백이 생기지 않는다
- **Logstash·Kibana를 빼는 것은 `flow.md` §18 원칙과 정확히 일치한다** —
  *"기술을 사용하기 위해 도메인을 억지로 설계하지 않는다."* 이미 있는
  관측 스택과 겹치는 것을 또 두지 않는다

## 대가

- **관리형 서비스 계정을 추가로 관리해야 한다.** Atlas 계정과 자격증명을
  `.env`와 별개로 보관해야 한다(k3s Secret으로 관리 — `ADR-013` 참조)
- **무료 한도를 넘으면 갑자기 막히거나 과금될 수 있다.** 사용량 알림을
  걸어둬야 한다
- **오리진이 하나 더 늘어난다.** OCI가 살아있어도 Atlas 쪽 장애면 채팅이
  죽는다 — 정산 기능(MySQL 기반)과 장애 도메인이 분리된다는 점은 오히려
  장점이다(부분 장애가 전체 장애로 안 번짐)

> **Atlas 무료 티어의 정확한 현재 한도·약관은 제 기억 기준이다.** 콘솔에서
> 최신 조건을 확인할 것. 위 메모리 수치도 전부 추정치이며, `bench/`
> 스크립트로 각 컴포넌트를 실측해 이 표를 갱신할 것.

## 재검토 조건

- Atlas 무료 한도(512MB)를 실사용 채팅량이 넘어설 때 → 자체 호스팅 재검토
  또는 유료 티어 전환
- Kafka가 자체 호스팅으로 안 맞을 때(측정 후 판단) → Redpanda로 교체
- Elasticsearch 도입 시점에 실측 용량이 부족하면 → 관측 스택 리텐션을
  더 좁히거나, 채팅 검색을 MongoDB Atlas Search(Lucene 기반, Atlas 내장
  검색 기능)로 대체해 별도 ES 클러스터 자체를 없애는 방안도 검토한다
