# 앱 영수증 촬영 프롬프트 · 2026-10-20

대화에서 정리한 프롬프트를 사용자 요청에 따라 나중에 다시 사용할 수 있도록 프로젝트에 보존한다.
프론트 구현 지시 전달·구현 완료를 의미하지 않는다. OCR 검증은 별도로 계속한다.

## 프론트 담당자에게 전달할 내용

정산어택 앱에 영수증 촬영·업로드 화면을 구현해줘. 기존 앱의 디자인과 구조를 먼저 확인하고,
영수증에서 술 종류·수량·금액·총액을 읽기 좋은 사진을 확보하고 사용자가 결과를 확인·수정하도록 해줘.

1. **촬영 화면**
   - 영수증 가이드를 표시하되 길이가 다양한 종이를 고정 비율에 억지로 맞추게 하지 말아줘.
   - 기본 안내는 “영수증 전체가 보이도록 정면에서 찍어주세요”. 상품명·수량·금액과 맨 아래 합계를 담도록 안내해줘.
   - 카메라와 갤러리를 지원하고 권한 거부 시 갤러리·직접 입력으로 이어지게 해줘.
2. **촬영 후 확인**
   - 미리보기·다시 찍기를 제공해줘. 기존 기능·기본 API가 지원하면 자르기·회전·수동 조정을 제공해줘.
   - 자동 자르기 영역도 사용자가 수정할 수 있게 해줘. 작은 숫자를 지우는 강한 압축·축소·보정은 피하고 선명도를 유지해줘.
   - JPEG·PNG 전송을 지원하고 필요한 경우 iOS HEIC를 변환해줘. 실제 서버의 용량·픽셀 제한을 연결 전에 대조해줘.
3. **품질 안내**
   - 잘림·흔들림·반사를 실제로 감지한 경우에만 해당 안내를 보여줘. 감지 기능이 없는데 감지한 것처럼 표시하지 말아줘.
   - 예: “영수증 아래쪽까지 담아주세요”, “흔들렸어요. 잠깐 고정해주세요”, “빛 반사를 피해 주세요”.
   - 애매하면 사용자가 확인하고 계속 진행할 수 있게 해줘.
4. **인식 중 상태**
   - 현재 15~17초 이상 걸릴 수 있으니 처리 중임을 명확히 표시해줘. 근거 없는 진행률·남은 시간은 표시하지 말아줘.
   - 중복 제출을 방지하고 실패 시 재시도·다시 촬영·직접 입력을 제공해줘. 화면 이탈 시 기존 앱 방식대로 상태를 정리해줘.
5. **인식 결과**
   - 총금액과 술 이름·수량·금액을 보여주고 수정 가능하게 해줘. 미인식 값은 빈칸·“확인 필요”로 표시해줘.
   - 수량을 임의로 1로 채우거나 이름만 보고 병 단위로 확정하지 말아줘.
   - 확인 전 기존 차수 입력값을 저장·덮어쓰지 말고 확인 후 기존 입력 화면에 반영해줘.
6. **서버 연결**
   - 앱 → Spring → Python OCR 구조야. Python 내부 API 직접 호출·내부 서비스 키 삽입은 하지 말아줘.
   - Spring 공개 OCR API 구현·계약을 확인해줘. 없으면 목 응답과 교체 가능한 연결부로 화면을 완성하고 필요한 계약을 정리해줘.
   - 목 응답을 실제 인식 결과로 설명하지 말아줘.

앱 촬영·확인·수정 흐름에 집중하고 웹은 기존 직접 입력을 유지해줘. 기존 의존성·플랫폼 기능을 우선 사용해줘.
새 라이브러리가 필요하면 필요성과 대안을 정리해줘. 완료 시 구현 범위·실기기 확인·목 처리·Spring 연결 필요 사항을 알려줘.

## 기억할 작업 방향

- 위 프롬프트를 다시 요청하면 이 파일을 기준으로 제공한다.
- 프론트 구현은 별도 저장소 담당자의 작업이다. 이 백엔드 저장소에서 앱 코드를 만들지 않는다.
- 원본 영수증을 늘려 OCR 테스트를 계속한다. 같은 원본의 파생본을 독립 표본으로 세지 않는다.
- 처음 보는 원본의 수정 전 결과를 보존하고, 개발에 사용한 뒤에는 독립 평가용이라고 부르지 않는다.
- 총액·주류 필드별 결과와 시간·실패를 함께 기록한다. 두 개발 사진의 2/2를 일반 정확도 100%로 설명하지 않는다.
