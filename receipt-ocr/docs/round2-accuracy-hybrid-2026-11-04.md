## 바꾼 것

- K345의 공개 profiler에서 기본 OCR11.015초 중 인식10.222초·검출0.787초를 확인했다.
- Paddle3.3.1에서 전체 oneDNN을 켰을 때 실제 오류가 [공식 OCR 이슈](https://github.com/PaddlePaddle/PaddleOCR/issues/18162)·
  [Paddle 이슈](https://github.com/PaddlePaddle/Paddle/issues/77340)의 PIR/oneDNN 서명과 같았다. 공개 old-IR 옵션도 실패했다.
- 검출은 기존 CPU로 두고 인식과 작은 숫자 인식기만 oneDNN을 사용한다. 공개 `load_pipeline_config`와 모듈별
  `engine_config`를 사용하며 비공개 객체를 바꾸거나 라이브러리를 추가·교체하지 않는다.
- `recognition_mkldnn=None`은 AMD64/x86_64에서만 활성화한다. ARM·미상은 기존 경로이며 False는 명시적 비가속 대조다.
  아키텍처 테스트는 모의 검사이고 실제 ARM 추론·성능 검증이 아니다.
- 전역 줄 묶기는 유지하고 명시 헤더·열 위치가 있는 실패 행만 다시 연결한다. 같은 숫자를 두 상품이나 옆 표에 빌리지 않는다.
- 이름 한정자·비알코올·특수 행·별도 `0.0/0,0/0`·부호·잘못된 숫자를 이전 음식 행으로 버리지 않는다.
  이전 행 예외는 이름→숫자의 세로 이동도 일관될 때만 허용한다. 이 거절 조건으로 정상 행을 놓칠 수 있다.
- 수량 열의 `개`는 개수로 읽고 병 단위를 만들지 않는다. HWARO의 단가와 용기는 계속 미상이다.
- 기존 개발 사진 K263/K203에서 확인한 정확한 `대선` 별칭만 추가했다. 새 평가3개의 제품명/결과로 사전을 고치지 않았다.

[진단·CPU 기록](round2-cpu-results.json)에는 실제 오류 서명·공개 인식 설정·단계별 시간·메모리·비교 실패도 보존했다.
초기 oneDNN 로그의 실행 primitive6984개는 실제 인식 가속 확인용이며 그때의 시간은 성능 비교에 사용하지 않았다.
