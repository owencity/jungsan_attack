## 범위와 정답

OCR 구현 기준은 `524ee20cfc15e18fce276758114c2c5947cc25f2`다. 이번에는 운영 OCR 코드·사전·모델·API를
바꾸지 않고 먼저 실패를 찾는다. 사용자 요청으로 앱 촬영 프롬프트를 MEMORY.md에서 찾을 수 있게 보존했다.
문서 기준 원격 main은 `3e37cb54d50253ac185223e7b26aee0fbe08fffa`다.

[manifest](../examples/manifest.capture-campaign.example.json)에 정답·출처·원본 SHA-256·묶음을 고정했다.
사진은 직접 보고 주류/비주류와 보이는 숫자를 표시한 후 모델을 실행했다. 결과를 보고 정답을 바꾸지 않았다.

- 기존 사진 8개 + 새 사진 8개 = 원본 이미지 16개, 매장/원본 묶음 15개다.
- 가라지 영수증과 메뉴판은 같은 묶음이다. 파생 이미지·재압축본·새 촬영 사진은 추가하지 않았다.
- 새 사진은 다른 매장·마트 영수증, 메뉴판, 금액이 가려진 도매 전표다. 마트/도매는 술자리 MVP 밖의 도전 사례다.
- R/T만 기존 전체 9필드 정답이다. G1/G2/P는 보이는 종류·단가·수량·항목 금액의 **부분 정답**이다.
  여러 줄 이름·숫자 괄호의 용량/팩 의미는 확정하지 않았다. 전체 9필드 정확도로 합치지 않는다.
- C1/C2는 술 없는 영수증이다. C3의 펀치는 같은 출처 메뉴의 Non-Alcoholic Beverage로 확인했다.
- W는 금액이 가려진 사진에서 가격을 만들어내지 않는지 보는 대조다. 빈 후보를 정확한 주류 추출 성공으로 세지 않는다.
- J는 이름 가림, N은 복수 영수증, F1/F2는 음식 대조다. 이 기대 응답을 실제 주류 정답으로 해석하지 않는다.
- 웹에서 고른 편의 표본이며 동일 블로그 촬영자 편향도 있다. 무작위/대표 표본·새 기기 촬영·독립 성능 인증이 아니다.

서로 다른 양식/글자 수와 PC 부하가 섞여 있다. 이전 실행보다 느려졌거나 개선됐다는 비율·운영 SLA로 쓰지 않는다.
`baseSeconds`는 최초 검출+전체 인식 묶음이다. 검출기와 인식기 각각의 실측 시간은 아직 없다.

1. C1/C2/C3에서 총액을 놓쳤다. 영수증의 합계 표기·기울기·행 묶기·OCR 누락을 좌표별로 구분하는 진단이 다음 순서다.
   지금 출력만으로 특정 원인을 확정하지 않았다. 정답 26,500/13,400/52,000원을 null로 바꾸지 않는다.
2. G1/G2의 여러 줄 상품명·상품코드 양식에서 주류 행이 누락됐다. G2는 총액을 읽었지만 주류는 읽지 못했다.
   임의 부분 문자열/유사도 허용 대신 상품명 줄과 숫자 줄 연결, 전체 이름 검증을 대조해야 한다.
3. M1 메뉴판에서 소주·위스키 하이볼을 후보로 반환했다. 수량/단가/금액/병 수는 null이다.
   메뉴판→주문 후보의 오인식이며 수량·금액 환각이 없다는 이유로 성공 처리하지 않는다.
4. B의 기존 총액 누락, P의 기존 주류 누락도 이번 목록에 남긴다. 지원하지 않는 사진을 성공 사진 목록에서 숨기지 않는다.

촬영 가이드·자르기가 이 실패를 해결했거나 시간을 단축했다고 주장하지 않는다. 자동 자르기·보정 실험은 아직 하지 않았다.
다음은 **백엔드 담당자의 총액 실패 진단 → 메뉴판 오인식 제한 → 여러 줄 주류 행 대조 → 화질/자르기/처리시간 비교**다.
각 수정 전후에 이 원본을 재실행하고, 수정에 사용한 사진은 개발 자료로 분류한다. 별도 매장 평가 표본은 계속 확보한다.
프론트 담당자의 촬영 화면 구현과 Spring 공개 업로드·권한·시간 제한 연결은 별도 후속이다.

## 재실행

기존 전용 venv·모델 캐시 환경에서 `receipt-ocr`를 작업 디렉터리로 사용한다.

```powershell
.venv\Scripts\python -m unittest discover -s tests
.venv\Scripts\python tools\validate_capture_campaign.py .samples/public-web --output reports/capture-campaign.json
```

원본은 저장소에 없다. manifest 출처에서 제공하는 사진과 SHA-256이 같은 로컬 파일을 준비해야 한다.
위 명령은 사진을 자동 다운로드하지 않는다. 링크 만료·접근 오류를 새 사진으로 대체해 동일 원본이라고 부르지 않는다.
도구는 SHA-256이 다르거나 실행이 실패하면 관측을 남기고, **하나라도 정답 불일치가 있으면 종료 코드 1**이다.
알려진 실패를 통과시키기 위해 expected를 수정하거나 테스트를 비활성화하지 않는다.

실제 모델 16개 첫 실행은 로컬 진단 스크립트로 단계별 시간을 기록했다. 그 JSON을 보존 도구의 비교 함수로 다시 대조한다.
OCR 원문·카드 번호·사진·HTML은 보고서/Git에 추가하지 않는다. 보고서는 검토된 표시명·필드와 비교 결과만 담는다.
정답 필드 비교는 영수증 위→아래 순서이며, 누락 행 이후 필드 비교도 실패한다. 필드 오류 개수를 개별 물리적 오류 개수로 합산하지 않는다.
