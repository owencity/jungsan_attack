# 영수증 OCR 작업 기억

## 사용자 결정 · 2026-10-20

- 앱 촬영 화면 프롬프트는 [보존 문서](docs/frontend-capture-prompt.md)를 다시 제공한다. 아직 프론트 담당자에게 전송하거나 구현한 것은 아니다.
- 백엔드 담당자는 OCR 테스트를 계속 늘린다. 같은 원본의 파생본과 처음 보는 원본을 구분한다.
- 사용자가 이미 승인한 하나의 작업 안에서 중간 구현 승인을 반복 요청하지 않는다. 작업을 마치고 결과·한계·후속을 함께 보고한다.
- 유료 API 없이 기존 PaddleOCR 한국어 CPU·Python 내부 API를 사용한다. 앱은 Spring을 거쳐 호출한다.
- 새로운 라이브러리·모델 선택, Spring 공개 업로드 구현, 앱 구현, 병합·운영 배포는 기존 완료와 구분한다.

## 검증 원칙

- 수량 1·단가·병 수를 기본값이나 가격 역산으로 채우지 않는다. 미인식은 null과 확인 사유를 유지한다.
- 전체 정답 9필드 평가, 일부 필드 도전 사례, 술 없는 영수증, 메뉴/음식/가림 대조를 구분한다.
- 실패도 분모와 기록에 남긴다. 정답을 모델 출력에 맞추거나 실패 사진을 삭제하지 않는다.
- 출처·원본 SHA-256·매장/원본 묶음·수정 전 결과·처리시간을 보존한다. 같은 매장/원본의 파생본을 평가 쪽에 섞지 않는다.
- 공개 사진도 Git에 넣지 않는다. 테스트 원본·모델·상세 로컬 보고서는 기존 ignore 폴더에 둔다.
- 두 개발 사진의 2/2나 단위 테스트 개수를 실제 영수증 일반 정확도로 설명하지 않는다.
